The closure report's verdict card follows the run's decision when the run reports one.

| Skill | Version | Status |
| --- | --- | --- |
| incident-investigation | 1.6.10 | released |

## What changed

- **render_closure.py:** an optional `verdict.disposition` (the agent portal's fixed set:

  `escalate_contain`, `confirmed`) and `verdict.severity` label and colour the card, as the

# 2026-11-13 — ciso-monthly-report 1.0.1 → 1.0.2

The report always carries a linked table of contents, and its links work in every PDF viewer.

| Skill | Version | Status |
| --- | --- | --- |
| ciso-monthly-report | 1.0.2 | released |

## What changed

- **build_report.py:** every chapter, numbered section and appendix part gets an anchor (`ch-N`, `s-NN`,
  `ap-X`), and a contents page built from those anchors is always inserted between the cover and chapter 1,
  each entry a link to its heading. New optional `--toc-pages` fills the page column from a JSON map.
- **scripts/render_pdf_with_toc.py (new):** renders through `fluency-report`'s `render_pdf.mjs`, writes each
  entry's PDF page number into the contents page, re-renders until the numbers are stable, rewrites the
  contents links as explicit page links (Chromium's named destinations do nothing in macOS Preview and
  several other viewers) and adds a bookmark outline. Needs PyMuPDF.
- **SKILL.md:** the contents page is mandatory; the PDF is always produced with `render_pdf_with_toc.py`;
  Step 4 checks the contents page and its links.
- `cowork/ciso-monthly-report.skill` rebuilt.

# 2026-11-13 — office365-posture-review 1.0.0 → 2.0.0

The posture review now renders the Microsoft 365 identity hygiene report (the office365-hygiene-report
layout and evidence) in the Fluency editorial style, computed from the resource dumps alone, with the
posture review's application and device registration checks kept as two extra sections.

| Skill | Version | Status |
| --- | --- | --- |
| office365-posture-review | 2.0.0 | released |

## What changed

- **Report layout (breaking):** title and thesis, five-tile scorecard, highest-impact finding, executive
  summary with rating, headline KPIs, privileged role footprint, MFA / token / password hygiene, OAuth
  consent, account composition, device OS currency, application registrations, device registration
  hygiene, analyst callouts, remediation sequence, method. Built with `fluency_brand.page()` and its
  components; no tinted, rounded or gradient styling.
- **New evidence:** headcount from licence tiers (disabled > guest > paid > free > add-on only >
  unlicensed); admins judged against 2 + 1 per 500 headcount; more than 2 Global Administrators; admin
  with a second weakness (Critical); guests above 15%; unlicensed members to classify; Windows end-of-life,
  out-of-support and to-confirm builds; macOS below 14; OAuth average, maximum and most common apps.
  Licence IDs not in the tier list are named, never guessed.
- **Narrative:** thesis, top finding, summary, callouts and remediation are generated from the numbers;
  `--narrative` replaces any of them (`references/narrative.md`).
- **Outputs:** `<out>.facts.json` (every figure and the narrative used) beside the HTML and CSV; one
  report per feed. New arguments `--account`, `--narrative`, `--facts`.
- **assets/sku_tiers.json, assets/os_catalog.json (new):** dated licence-tier map and OS catalogue, ported
  from office365-hygiene-report 1.0.0.
- Weak MFA stays case-insensitive and absent fields stay "not measured"; the hygiene skill's scripts miss
  both on tenants whose snapshot uses camel-case methods or lacks token fields.
- `cowork/office365-posture-review.skill` rebuilt.
