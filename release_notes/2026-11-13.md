# 2026-11-13 — incident-investigation 1.6.9 → 1.6.10

The closure report's verdict card follows the run's decision when the run reports one.

| Skill | Version | Status |
| --- | --- | --- |
| incident-investigation | 1.6.10 | released |

## What changed

- **render_closure.py:** an optional `verdict.disposition` (the agent portal's fixed set:
  `closed`, `closed_suggested_action`, `closed_per_note`, `closed_verify`, `escalate_confirm`,
  `escalate_contain`, `confirmed`) and `verdict.severity` label and colour the card, as the
  portal's opening line does. A low-severity confirmation closed on an `escalate` outcome now
  reads "Closed: verify · Low" in green instead of "Escalate". A closure with no disposition
  still shows its outcome. An unknown disposition or severity is refused.
- **closure_schema.md:** the two fields.
- `cowork/incident-investigation.skill` rebuilt.

# 2026-11-13 — ciso-monthly-report 1.0.1 → 1.0.2

The report always carries a linked table of contents, and its links work in every PDF viewer.

| Skill | Version | Status |
| --- | --- | --- |
| ciso-monthly-report | 1.0.2 | released |

## What changed

- **build_report.py:** every chapter, numbered section and appendix part gets an anchor (`ch-N`, `s-NN`,
  `ap-X`), and a contents page built from those anchors is always inserted between the cover and chapter 1,
  each entry a link to its heading. New optional `--toc-pages` fills the page column from a JSON map.
- **scripts/render_pdf_with_toc.py (new):** renders through `fluency-report`'s `render_pdf.mjs`, writes each
  entry's PDF page number into the contents page, re-renders until the numbers are stable, rewrites the
  contents links as explicit page links (Chromium's named destinations do nothing in macOS Preview and
  several other viewers) and adds a bookmark outline. Needs PyMuPDF.
- **SKILL.md:** the contents page is mandatory; the PDF is always produced with `render_pdf_with_toc.py`;
  Step 4 checks the contents page and its links.
- `cowork/ciso-monthly-report.skill` rebuilt.
