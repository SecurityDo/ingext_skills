# 2026-10-12 — fpl-report-dashboard 1.0.0 (new)

New skill for building dashboard reports (an `fpl_report` processor plus its panels and
layout), from the Windows host-health dashboard built for a customer that day.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| fpl-report-dashboard | 1.0.0 | released |
| fpl-report-builder | 1.0.1 | released |
| fluency-report | 1.0.1 | released |

## Why

No skill covered the dashboard path: reportConfig panels and layout, report arguments,
metric data sources, deploying a report with its layout (`ingext processor add` cannot carry
it), testing with `run_report`, or the release. The first dashboard shipped with every chart
reading zero in the UI because the range was not aligned to the interval, which short test
windows did not reveal.

## Changes

- **fpl-report-dashboard (new):** data sources (`Platform_Metric_Query`/`QueryRange`,
  `jsonTable`), the aligned-range rule for metric charts, legends, panels and the 16-column
  layout, FPL pitfalls in report code, builtin availability per tenant version, and the
  workflow (pending draft, processor test, test copy with reportConfig, `run_report` at 50+
  points, release, post-sync check). References: `references/panels.md` (panel JSON per type,
  from reports that render today). Assets: `deploy_report.py` (posts the entry to
  `platform_processor_dao`), `WinHost_Health_Report.js/.json` (worked example).
- **fpl-report-builder 1.0.1, fluency-report 1.0.1:** point to fpl-report-dashboard for
  building dashboards.
