## Implementation notes

- **ingext-kql (1.0.2 → 1.0.3)** — re-synced the embedded schema knowledge base from the
  `ingext_schema` repo via `scripts/sync_schemas.py`. `references/schemas/manifest.json`
  regenerated (24 → 30 tables). Verified with `sync_schemas.py --check` reporting the KB up to
  date.
  - **Six new tables added**, each with its `info.yaml` schema doc and two example queries under
    `queries/`: **AbnormalCase**, **AbnormalThreat** (Abnormal Security), **FalconAlert**
    (CrowdStrike), **falconAgent** (CrowdStrike Resources), **CloudTrail** (AWS CloudTrail), and
    **F5BigIPLTM** (F5 BIG-IP LTM).
  - **Zscaler numeric-type correction (behavioural).** The `ZscalerDNS`, `ZscalerFirewall`, and
    `ZscalerWeb` schema docs were updated to reflect that the NSS feed parser now emits the
    numeric fields as native numbers rather than JSON strings. The old "arrives as a string; cast
    with `toint()`/`tolong()`/`todouble()`" guidance was removed from the affected field
    descriptions and the table notes, and the byte/size fields that were mislabeled `Integer`
    were corrected to `Long` (`inbytes`, `outbytes` on ZscalerFirewall; `reqsize`, `respsize` on
    ZscalerWeb). Queries over these tables no longer need explicit numeric casts before
    arithmetic or comparison.
  - No other existing table schemas changed, and `SKILL.md` resolves tables dynamically from the
    manifest, so no prose/behaviour changes were needed beyond the version bump.
