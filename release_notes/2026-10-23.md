# 2026-10-23 — fluency-report-rollup 1.0.0 (new)

| Skill | Version | Status |
| --- | --- | --- |
| fluency-report-rollup | 1.0.0 | released |

**Monthly, quarterly and trend reports from a scheduled report's daily archive.** A scheduled
report with the archive enabled runs once a day for exactly the previous day. Each result is
kept for 12 months (platform 9.0.12, api 9.12.42). The skill assembles longer periods from
those dailies rather than running one long report.

- **Pipeline:**
  1. `list_report_archive` checks coverage: missing, aborted and running days, and script changes.
  2. `backfill_report_archive` fills gaps, if the user agrees.
  3. `processor_get` reads the script, to decide how each table merges.
  4. `download_report_archive` fetches up to 92 days per call.
  5. `scripts/rollup.py` merges them, and the result is spot-checked against `run_report`.
  6. fluency-report renders the page.
- **`references/merge_rules.md`:** covers each merge mode (sum, timebucket, top, aggregate,
  max/min/last, concat), lists what can't be merged (ratios, percentiles, distinct counts with
  no per-key table), and gives a worked check.
- **Two time-series traps found on real data:**
  - Metric range buckets are labelled by their end.
  - Each daily run also returns the bucket that straddles its start.

  Summing naively puts the per-day series off by about +4% and shifts it by a day.
- **Validated on titan:** `System_Event_Ingress_Report`, 30 backfilled days (2026-09-23 ..
  2026-10-22), compared with one direct 30-day run.
  - Every keyed total is within 0.02%.
  - The grand total is within 0.0002%.
  - The per-day series is within 0.001%.
  - The top-N orders are identical.
- The archive tools are only on tenants running api 9.12.42 or later. At release, that is
  titan only.
