# 2026-07-29 — ingext-kql schema sync (Duo, Zscaler ZPA, SentinelOne, Windows Audit, Microsoft Defender) + query validation pass

One skill update. `ingext-kql` had its embedded schema knowledge base re-synced from the
`ingext_schema` repo across several schema updates — adding fifteen tables and re-casing one —
then every example query was validated against the live platform KQL parser and the queries the
parser rejects were removed. For what each skill does and its trigger phrases, see its section in
the root `README.md`.

## Implementation notes

- **ingext-kql (1.0.3 → 1.0.4)** — re-synced the embedded schema knowledge base from the
  `ingext_schema` repo via `scripts/sync_schemas.py`. `references/schemas/manifest.json`
  regenerated: **30 → 44 tables**, 88 example queries.

  - **Fifteen new tables**, each with its `info.yaml` schema doc and example queries:
    - Identity / MFA: **DuoAdmin**, **DuoAuthentication** (Cisco Duo).
    - Network: **ZPAUserActivity** (Zscaler Private Access).
    - Endpoint / EDR: **SentinelOneActivity**, **SentinelOneAlert**, **SentinelOneThreat**.
    - Windows: **WindowsAudit** (Security event log).
    - Microsoft Defender (event): **MSDefenderAlert**, **MSDefenderIncident**.
    - Microsoft Defender (resource snapshots): **msDefenderMachine**, **msDefenderAvHealth**,
      **msDefenderVulnerability**, **msDefenderRecommendation**, **msDefenderSecureConfig**,
      **msDefenderSecureScore**.

  - **`sentinelOneThreat` re-cased to `SentinelOneThreat`.** The SentinelOne threats table
    identifier changed casing in the schema repo; the old lowercase folder was removed and the
    capitalized table added (now carrying `s1-open-threats` and the new `s1-threats-by-mitre-tactic`).
    On the case-insensitive workstation filesystem this is a case-only rename, so a future commit
    needs an explicit `git rm --cached` of the lowercase path plus re-add of the capitalized one.

  - **Query validation pass.** Every example query was checked with the platform `validate_kql`
    parser (parse-only; no searches executed). Five queries the parser rejects were removed from
    the skill:
    - `MSDefenderAlert/msd-alert-file-process-iocs` and
      `msDefenderRecommendation/mde-recommendations-priority` — use `Kind` as a column alias;
      `Kind` (case-insensitive) is a reserved word in this parser (from `join kind=`).
    - `msDefenderRecommendation/mde-recommendation-affected-devices` — uses `union` as a leading
      pipeline operator, which the parser does not accept.
    - `msDefenderSecureScore/mde-secure-score-headroom` — uses `toscalar(<tabular | pipe>)`;
      `toscalar` here only accepts a scalar expression, not a piped subquery.
    - `sentinelOneApplication/s1-application-inventory` — compares an aggregate inline inside
      `summarize` (`countif(signed == false) > 0`), which is not allowed.

  - **Parser update fixed three earlier failures — those queries were kept.** A platform KQL
    parser update means constructs that failed on an earlier build now validate, so the affected
    queries stay in the skill:
    - Negated operators `!in` / `!endswith` / `!startswith` and `project-away` — now valid.
    - Bracket indexing of a dynamic field (`descriptionFields["Users seen"]`) — now valid, so
      `DuoAdmin/duo-directory-sync-health` (excluded on the previous build) is back and passing.
    - String literals ending in a backslash inside a `has_any(...)` list (`"\\users\\"`) — now
      valid, so `WindowsAudit/wa-suspicious-process-creation` (also previously excluded) is back
      and passing.

  - **Engine note:** `MSDefenderAlert/msd-alert-device-evidence-argmax` uses `arg_max(<col>, *)`.
    The Develop connector's parser accepts the wildcard; the Titan connector's does not. It was
    kept (it documents this requirement and ships a portable twin, `msd-alert-device-evidence`,
    that avoids the wildcard).

  - No prose/behaviour changes to `SKILL.md` beyond the version bump — the skill resolves tables
    and example queries dynamically from the manifest.

### Follow-ups

- The five removed queries were excluded from the skill only; the source `ingext_schema` repo
  still contains them, so a future sync will reintroduce them unless they are fixed or removed at
  the source. All five are fixable (rename the `Kind` columns; replace `union`/`toscalar` with
  join-based forms; move the aggregate comparison to an `extend` after `summarize`).
