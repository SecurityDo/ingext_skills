# 2026-09-29 — incident-investigation 1.2.2 → 1.2.3, ingext-get-profile 1.0.0 → 1.0.1

Don't call `list_accounts` when the caller already verified the account.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| incident-investigation | 1.2.3 | released |
| ingext-get-profile | 1.0.1 | released |

## Why

Step 0 confirmed the target account with `list_accounts`, once. On a provider's grid
connector that call returns **every customer on the connector**, and it lands in the
run's conversation and stored trace. The Agent Portal runs this skill against one
account whose name it already knows, and may later show that trace to the account's
own users. They would see the provider's whole customer list.

The confirmation still matters when a person types the name: the grid proxy serves
the provider's own manager account for an unknown name instead of failing. The Agent
Portal now does that check server-side before the run and never shows the list to the
model.

## What changed

- **incident-investigation**
  - The hard rule no longer allows `list_accounts` unconditionally. When the caller
    supplies a verified account (the Agent Portal says so in its prompt and blocks the
    tool), the skill never calls it. Only an interactive run, where a person typed the
    name, confirms it once, and uses nothing else from the list.
  - Step 0 ("Targeting is per call") is split into those two cases.
  - The closure's `Tenant` display name comes from the caller when given, else from
    the interactive confirmation; `closure_schema.md` matches.
- **ingext-get-profile**: the same condition on its standalone confirmation.
