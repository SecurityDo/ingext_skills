# 2026-08-19 — ingext-kql schema KB resync (Google Workspace added; Microsoft Defender rewrites) + full query validation

One skill update. `ingext-kql` had its embedded schema knowledge base resynced from the
`ingext_schema` repo via `scripts/sync_schemas.py`, and every example query in the skill was then
validated against the live platform KQL parser. This release consolidates the schema changes made
since 1.0.4 (including an interim 2026-08-14 resync that was never committed). For what the skill
does and its trigger phrases, see its section in the root `README.md`.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| ingext-kql | 1.0.5 | released |

## Implementation notes

- **ingext-kql (1.0.4 → 1.0.5)** — resynced the embedded schema KB under `references/schemas/`
  and its `manifest.json` from `ingext_schema`. `--check` is clean: **46 tables, 108 example
  queries** (up from 44 tables at 1.0.4).

  - **Two new tables**, each with eight example queries:
    - **`GSuite`** (Google Workspace audit activity) — activity overview, suspicious logins,
      OAuth app grants, Drive external sharing, Drive mass-access, Calendar external disclosure,
      device posture, and a per-user activity timeline.
    - **`GoogleWorkspaceAlert`** (Google Workspace Alert Center) — overview, triage,
      account warnings, DLP violations, phishing campaigns, phishing IOCs, response latency,
      and correlation with `GSuite` login/grant/share activity.

  - **Microsoft Defender queries rewritten.** All `MSDefenderAlert` and `MSDefenderIncident`
    example queries were reworked to reduce each record to its newest snapshot with the now-supported
    `arg_max(lastUpdateDateTime, *)` wildcard (replacing the earlier `let` + `max()` + `join`
    workaround), and the reserved-word column alias `Kind` was renamed (`IocType` in
    `msd-alert-file-process-iocs`, `RecType` in `mde-recommendations-priority`). The
    `msd-alert-device-evidence-argmax` variant was removed from source (its wildcard form is now
    the norm). `mde-recommendation-affected-devices` was generalized to accept a list of
    recommendations.

  - **All previously-excluded queries are now valid.** The five queries held back in earlier
    releases all validate again — three were fixed at the source (the two `Kind` renames and the
    `union`-based `mde-recommendation-affected-devices`), and two more
    (`mde-secure-score-headroom`, using `toscalar(<tabular pipe>)`, and `s1-application-inventory`,
    using an inline aggregate comparison) now pass because the platform KQL parser was upgraded to
    accept those constructs. No queries are excluded from the skill any more; the KB is a 1:1
    mirror of `ingext_schema`.

  - **Full validation pass.** Every one of the 108 example queries was checked with the platform
    `validate_kql` parser (parse-only; no searches executed) against the `titan` tenant. **All 108
    validate.**

  - **Cowork package rebuilt.** `cowork/ingext-kql.skill` was regenerated from the updated source;
    its embedded manifest reports 46 tables / 108 queries. Archive layout unchanged.

- **Verification.** `python3 scripts/sync_schemas.py --repo ../ingext_schema --check` reports the
  embedded KB is up to date (46 tables), and all 108 queries pass `validate_kql`.
