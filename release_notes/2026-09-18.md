# 2026-09-18 — ingext-kql: `ASSET` fixed system table added

One skill update. `ingext-kql` gained a new queryable table, `ASSET`, which surfaces the
platform's global asset inventory (the same data the `asset_search` MCP tool returns) via
KQL. Unlike every other table in the KB, `ASSET` is **not** sourced from the `ingext_schema`
repo and does not appear in `list_data_tables` or `manifest.json` — it was found and added by
hand after direct verification against a live tenant. For what the skill does and its trigger
phrases, see its section in the root `README.md`.

## Implementation notes

- **ingext-kql (1.0.5 → 1.0.6)** — added `ASSET` as a hand-maintained "fixed system table."

  - **How it was found.** The user asked for an "ASSETS" table to back the same data as
    `asset_search`. `ASSETS`, `Asset`, and `AssetInventory` all failed to resolve
    (`table not found`) via `kql_search` against `fabrikam`. `ASSET` (singular, all caps)
    resolved and returned rows on `contoso`, with a column schema that lines up closely with
    `asset_search`'s documented fields (`name`, `fqdn`, `description`, `category`,
    `machineType`, `os`, `publicIP`/`privateIP`, `vendor`, `uuid`, `serialNumber`, `agentID`,
    `lastLoggedInUser`, cloud fields, `groups`, `tags`, `flags`, `providers`, `status`,
    `updatedOn`, `id`, plus a few fields not documented by `asset_search`: `model`,
    `platform`, `osVersion`, `location`, `profileType`, `trustType`, `username`, `createdOn`,
    `site`, `infos`).

  - **New schema doc.** `references/schemas/ASSET/info.yaml` — 34 fields, hand-written from
    the live column list (types/names verified; a handful of field semantics — `profileType`,
    `trustType`, `infos` — are flagged in their descriptions as not yet confirmed against a
    populated sample, since this repo's rule is never to invent field meaning). Marked in the
    doc itself as NOT part of the `sync_schemas.py`-generated KB, so a future resync won't
    remove it and won't know to update it either.

  - **New example query.** `references/schemas/ASSET/queries/asset-inventory-overview.yaml` —
    counts assets by category/machineType/provider with a status set per group. Validated with
    `validate_kql` against `fabrikam` and executed against `contoso` for real (sanitized) sample
    output.

  - **`SKILL.md` changes** — new "Fixed system tables" section (between "Tables and the
    datalake — key facts" and "Tools") listing `ASSET` and explaining that fixed tables have
    no `list_data_tables`/`manifest.json` entry, so they're checked separately. Workflow step 1
    ("Pick the table") now also checks this list. Workflow step 2 ("Load the schema") now
    routes a fixed table straight to its `info.yaml`, skipping the manifest lookup.

  - **Known gap, called out in the schema doc and the new SKILL.md section:** on `fabrikam`,
    `ASSET | take 10` returned 0 rows across a full 2025–2026 window, while `asset_search`
    returned 6 assets for the same tenant. The KQL-side table can apparently lag or diverge
    from the `asset_search` index for some tenants. The skill is instructed to say so
    explicitly (and suggest `asset_search` as a fallback) rather than report "no assets" when
    this happens.

  - **`README.md`** — added a "Try" example for the new table under `ingext-kql`.

  - **Cowork package rebuilt.** `cowork/ingext-kql.skill` was regenerated from the updated
    source (a stored/uncompressed zip of the `ingext-kql/` folder, matching the existing
    package's format) and now reports 260 files (up from 256), including the new `ASSET`
    schema and example query. Archive integrity verified with `unzip -t`; confirmed
    `SKILL.md` inside reads `version: 1.0.6`.

- **Verification.**
  - `ASSET | take 10` and the new example query both pass `validate_kql` against `fabrikam`.
  - The example query was executed against `contoso` and returned real data matching the
    `expected_output` in the query YAML.
  - Both new YAML files parse cleanly with `yaml.safe_load`.
  - `manifest.json` was **not** touched (it's auto-generated; `ASSET` is intentionally kept
    out of it and documented as an exception in both `SKILL.md` and `info.yaml`).
