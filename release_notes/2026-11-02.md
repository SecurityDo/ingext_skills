## microsoft365-resource-inventory-report 1.0.0 — new

**An archive-only Microsoft 365 / Entra directory inventory**, built the same way as the other archive-only
activity reports. It reads only the archive of the scheduled report `Office365_Resource_Inventory_Report`
(FPL processor id 720182 in the Scripts repo) and never searches live.

- Users, administrators (isAdmin flag or any directory role), MFA registration, and the **named list of enabled
  users with no MFA**, administrators first; devices; Conditional Access policies by state; app registrations,
  client-secret hygiene and app-only permissions; enterprise applications; groups; licensed users with users per
  license.
- The directory tables are snapshots. The report uses the latest archived day in the period and shows a trend
  over the archived days; days are never added, and a backfill records today's directory, not a past state.
- `--interactive` writes one self-contained HTML file (tabs, search, sort and filter on the user lists, CSV export,
  hover trend charts, dark mode). Print-style HTML, PDF and CSV as in the other report skills.
- The lists name people, so the report and archive are personal data; `--no-actors` leaves the lists out.
- Dry run on a 2,752-user tenant: all ten scans ran in about 13 seconds; the no-MFA list matches the count (1,337).

## billing-csv 1.3.0 — slimmer CSV

**billing-csv** now writes a slimmer CSV:

- Columns are `Client, Billing From, Billing To, Billed Days, Paid Users (M365), eventwatch_bytes, datalake_bytes, Note`.
- `datalake_bytes` is `lake_ingress_bytes − eventwatch_bytes` (clamped to 0 and flagged in `Note` if eventwatch is higher). The other ledger meters (`input_bytes`, `platform_datalake_bytes`, `lake_search_bytes`, `lake_realtime_search_bytes`, `deleted_bytes`, `processed_bytes`) are no longer written unless the user asks.
- The TOTAL row sums only the two byte columns; `Billed Days` and `Paid Users (M365)` are left blank. Lower-bound notes still name the affected tenants.
- One CSV per provider when several are billed. When the office365User dump count cannot be done (many tenants, or a quick run), the documented fallback is the ledger's `paidUsers` on the last billable day, reported as the ledger's observed seat count.
- For providers with many tenants, `usage_daily` calls are delegated to subagents that return compact JSON.
- An unavailable ledger now leaves the two byte columns blank instead of a per-meter list.
- Package `cowork/billing-csv.skill` rebuilt.

## microsoft365-entra-activity-report 2.0.0 — user ID when the name is empty (no version bump)

Sign-ins with an empty `UserPrincipalName` were listed as `(not recorded)` in the user and failed-user lists. The
report script now falls back to the user object ID (`UserId`), and shows `(not recorded)` only when both are empty
(`GetSigninFacets` and `GetNiFacets` in `Office365_Entra_Activity_Report.js`, which also changes the `user` and
`failedUser` facets). No other table changes. `references/archive_format.md` now says so, and
`cowork/microsoft365-entra-activity-report.skill` is rebuilt. The processor in the Scripts repo carries the same
edit and has to be released to tenants before archived days contain the IDs.
