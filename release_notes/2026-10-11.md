# 2026-10-11 — parser-rule 1.0.0 (new)

New skill for parser rules: registered EventWatch rules whose matching runs in an FPL channel
rule, which emits the rule's signal lines into the `CorrelationService` sink.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| parser-rule | 1.0.0 | released |

## Why

Parser rules (design: cloudv2 `docs/parser_rules_v2_design.html`, Part B) let a rule's
matching live in the parser while fsm_service, mantis and the behavior summary service handle
its signals like a static rule's, so a parser release does not restart the rule's warm-up.
Authoring one touches three objects (rule, channel rule, caller) and several tools, and the
failure modes are silent: a missing sink, a line in milliseconds, a caller overwritten by a sync.

## Changes

- **SKILL.md (new):** choosing a parser rule; tenant requirements (api 9.12.31, rule test on
  api 9.12.32 + platform 9.0.6, fsm 3.3.2, the CorrelationService sink); the rule file and the
  never-matching selector; hit and aggregation line formats; writing the channel rule; local
  validation with `fplJobValidate -signals`; deploy and `rule_test`; a site-local caller pipe
  (priority 1500, returns `"abort"`) instead of editing a released processor; verifying with
  fsm_service's `parserSignalFile` keep/drop counts; side-by-side comparison and warm-up;
  release with `sync_cli` (rule and fplProcessor separately); gotchas.
- **assets (new):** the kql pilot's parser rules (`parser-rule.json`,
  `parser-rule-aggregation.json`), channel rules (`channel-rule-hit.js`,
  `channel-rule-aggregation.js`) and the site-local caller (`channel-caller-local.js`). Both
  rules pass `sync_cli`'s parser-rule check.
- **cowork/parser-rule.skill (new):** the installable package (SKILL.md and assets).

## Verified

On tenant `kql` (terplab): both `_local` parser rules hit in `rule_test` with signal lines and
behavior event identical to their static twins apart from the rule name; `fplJobValidate
-signals` on the asset set with kql samples records 5 lines, 0 failures, 0 warnings.
