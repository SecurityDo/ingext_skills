## What changed

- New stream table: `Okta` (21 fields, 6 example queries), from `ingext_schema`
  `datatypes/Okta/`. Dynamic JSON (root `@okta`), fields referenced bare; `timestamp` equals
  `published`.
  - The schema warns about six traps. One sign-in is several records sharing
    `authenticationContext.externalSessionId`, so logins are counted on `user.session.start`.
    `client.ipAddress` can be a back end signing users in on their behalf. `VERIFICATION_ERROR`
    means the username does not exist, not a wrong password. Empty values are literal strings
    (`"null"`, `"unknown"`). Okta's risk and behavior verdicts should be read from
    `securityContext`, not the map strings in `debugData`. Self-joins need a `let` per side.
  - The example queries cover: unknown-user spraying from one IP, successful sign-ins by
    scripting clients, sign-ins Okta flagged as new country and new ASN, three or more users
    signing in from one IP within a minute, a user's sessions with the apps they opened, and
    security-relevant admin changes.
- **SKILL.md:** the join note now says self-joins must bind each side to a `let`. An inline
  same-table right side returns nothing after a `summarize` and undercounts before one, with no
  error (engine bug; fix pending).
- No other table changed. `--check` passes against `ingext_schema` (51 tables).
  `cowork/ingext-kql.skill` rebuilt.
