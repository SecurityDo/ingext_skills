# 2026-10-08 — ingext-entity-tables 1.0.0 (new)

New skill for discovering and searching Ingext entityinfo (lookup) tables: the
`ENTITY_*` tables that hold event-ID descriptions, status and reason codes, watchlists,
whitelists and blacklists, critical assets/users/subnets, license SKU names and AgentID
translations.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| ingext-entity-tables | 1.0.0 | released |

## Why

Entity tables are not returned by `list_data_tables` and have no entry in the ingext-kql
schema KB, so there was no way to find out which lookup tables a tenant has, what their
columns are, or how to write the KQL identifier. A new `list_entity_tables` MCP tool now
returns each table's `name`, `kqlName`, `fields`, `lookupType` and description per tenant.

## Changes

- **SKILL.md (new):** replaces the TODO stub. Workflow: pick the tenant, call
  `list_entity_tables`, choose the table, draft a single-table KQL query using the returned
  `kqlName` and `fields`, validate with `validate_kql`, run with `kql_search`, and return
  the query and a short explanation.
- **Search patterns:** preview (`take`), filter (`contains`), exact key lookup, count, and
  tables whose names or columns contain spaces (bracket-quoted).
- **Gotchas:** every column is a string; spaced names need brackets; an empty `kqlName`
  means the table cannot be queried; tables imported with no rows are listed but return no
  rows (on `titan`, `ENTITY_Group_Critical_Subnets` and `ENTITY_AD`); the catalog differs
  per tenant; `lookupType` (`string_match`, `prefix`, `CIDR`, `translation`) hints at how
  to read the values.
- **references/search_patterns.md (new):** the single-table query patterns above.
- **Scope:** searching entity tables on their own only. Joining entity tables to event
  tables for enrichment is deliberately left to a separate skill.

## Verified

Tested on tenant `titan` through the Develop connector: 45 entity tables listed, and the
search patterns returned real rows from `ENTITY_AD_EventID`, `ENTITY_AD_LogonType`,
`ENTITY_O365_Administrative_Operations`, `ENTITY_Exchange_Uncommon_Operations` and
`ENTITY_Microsoft License List`.

# 2026-10-08 — ingext-kql 1.0.9 → 1.1.0

`ingext-kql` can now enrich datalake queries with entity (lookup) tables using `join`,
including matching IPs to subnets from a CIDR table.

## Skills updated

| Skill | Version | Status |
| --- | --- | --- |
| ingext-kql | 1.1.0 | released |
| ingext-entity-tables | 1.0.0 | cross-link added, version unchanged |

## Why

Entity tables (`ENTITY_*`) hold the descriptions, watchlists and subnet definitions that
make raw events readable, but `ingext-kql` had no knowledge of them: they are not in
`list_data_tables` or the schema KB, so it could not discover them or join them in.

## Changes

- **SKILL.md, new "Entity tables (enrichment with JOIN)" section:**
  - discover with `list_entity_tables`, use `kqlName` and `fields` verbatim;
  - all columns are strings, spaced names need brackets, no time filter on the entity side;
  - sample both sides first and normalise keys with `extend` (for example
    `strcat(ActivityDisplayName, ".")`);
  - use `join`, not `in (<entity> | project ...)`, which does not parse;
  - inner join to filter, leftouter to enrich, leftouter + `isempty()` as an anti-join;
  - read `lookupType` (`string_match`, `prefix`, `CIDR`, `translation`);
  - an empty entity table gives no rows, which is not "no matches";
  - worked equality-join example and the CIDR example (cross join on a constant key,
    `ipv4_is_in_range`, longest-prefix match with `arg_max(prefix, ...)`).
- **SKILL.md workflow:** new optional step 4b, "Enrich with an entity table"; the tools
  table lists `list_entity_tables`; `tables` in the output contract includes any `ENTITY_*`
  table joined in.
- **references/entity_joins.md (new):** six worked JOIN samples — equality (inner), left outer
  flagging, anti-join, license SKU lookup from `office365User`, prefix lookup, and CIDR
  longest-prefix match — each marked as ran or parses, plus pitfalls found while testing.
- **ingext-entity-tables:** now points to `ingext-kql` for JOIN enrichment (description and
  intro only).
- **cowork packages** `ingext-kql.skill` and `ingext-entity-tables.skill` rebuilt.

## Verified

On tenant `titan`, these ran and returned rows: the Azure AD audit equality join, the left outer
flag (356 admin-operation events vs 8,673 other over 30 days), the anti-join, the license SKU lookup
(for example Microsoft 365 Business Standard: 9 users), and the prefix cross join (executed on Azure AD
audit activity names). The CloudTrail form of the prefix join parses only: `titan`'s CloudTrail returned
no rows. The CIDR query
parses with `validate_kql` (using `ENTITY_Group_Critical_Subnets`) but was not executed
with data: that table is empty on `titan` and no tenant checked had a populated CIDR table.
The `ENTITY_Corporate_Subnets` name in the example is illustrative and must be replaced
with a real `kqlName` from `list_entity_tables`.
