# 2026-07-08 — new skill: create-ingext-audit-app (Entra app registration for audit import)

One new skill. `create-ingext-audit-app` guides an Azure AD / Entra admin through registering the
**`ingext-audit`** application — a customer-owned, app-only (client-credentials) registration that
Fluency / Ingext authenticates as to import **Office 365 Management** audit events, **Azure AD /
Entra** audit events, and **Azure AD resources** (users, groups, devices, applications). It is a
stage in customer onboarding: the next stage ("install application") consumes exactly three fields
the skill produces — `tenantId`, `clientId`, `clientSecret`.

This is a **guide-the-user** skill (Claude cannot run against the customer's tenant — it needs the
admin's interactive sign-in), and it is net-new content for the repo: no prior app-registration
walkthrough, no PowerShell, and seven of its nine permissions were undocumented. It is distinct from
`add-connector`, which onboards Microsoft data through Fluency's **hosted** OAuth consent flow
(multi-tenant app + `adminConsentEmail`); this skill sets up a **customer-owned** app instead.

## Implementation notes

- **New skill `create-ingext-audit-app` (1.0.0).** Structure follows the `add-connector` template
  (interactive onboarding voice) plus the standard `assets/` + `evals/` layout.
  - **Two paths.** A recommended PowerShell path (`assets/setup-ingext-audit.ps1`, Microsoft.Graph
    SDK) and a manual Azure-portal walkthrough. Both create the single-tenant `ingext-audit` app,
    add the permissions, grant admin consent, and mint a 24-month client secret.
  - **Nine Application permissions across two APIs.** Microsoft Graph
    (`00000003-0000-0000-c000-000000000000`): `Directory.Read.All`, `AuditLog.Read.All`,
    `Policy.Read.All`, `Reports.Read.All`, `UserAuthenticationMethod.Read.All`,
    `MailboxSettings.Read`. Office 365 Management APIs
    (`c5393580-f805-4401-95e8-94b7a6ef2fc2`): `ActivityFeed.Read`, `ActivityFeed.ReadDlp`,
    `ServiceHealth.Read`. All are `type = Role` (app-only). A standalone reference lives in
    `assets/permissions.md`.
  - **No hardcoded permission GUIDs.** The script resolves each permission's app-role ID at runtime
    from the resource service principal's `AppRoles` (matched by `Value`, `AllowedMemberTypes`
    contains `Application`), so only the two well-known resource application IDs are constants. The
    script is idempotent (reuses an existing `ingext-audit` app), instantiates the Office 365
    Management APIs service principal if the tenant lacks it, and grants consent via
    `New-MgServicePrincipalAppRoleAssignment` per permission.
  - **Deterministic handoff.** The skill ends by emitting the three fields both human-readably and
    as a JSON object (`{ tenantId, clientId, clientSecret }`) so the calling onboarding task can
    parse them. It intentionally does **not** start Office 365 subscriptions or configure the
    Fluency connector — those are later stages.
  - **Docs.** Added a `README.md` table row and a "Platform operations" section with `**Try:**`
    prompts. `evals/evals.json` carries three trigger cases (script path, manual path, general
    onboarding).
