
# 2026-10-28 — compliance-assessment 1.6.0

| Skill | Version | Status |
| --- | --- | --- |
| compliance-assessment | 1.6.0 | released |

**CloudTrail now comes only from the archive.** The five `ct_*` searches (events, console logins, IAM changes, root
events, errors) are gone. The skill reads the archived days of the scheduled report `CloudTrail_Activity_Report`
(`download_report_archive`, saved as `ct_archive.json`) and `build_report.py` sums the daily trend rows for the month.

- If the tenant has a CloudTrail table and no day of the month is archived, the skill stops the CloudTrail part and tells
  the user the archive is required (`--require-cloudtrail` makes the build exit 3 with that message). It never runs a
  CloudTrail search as a substitute, including `src_CloudTrail` and `history_CloudTrail`.
- Missing days are a gap, never zero: the source reads "CloudTrail (N of M days archived)" and the gaps section lists the
  missing days and the backfill.
- The CloudTrail facts in `compliance_summary.json` gain access-denied, logins without MFA, CloudTrail changes and the
  coverage fields (`days_archived`, `days_expected`, `missing_days`).
- Tested on the audit tenant: September (30 of 30 days) gives 79,450,291 events, 18 failed console logins, 14,245 IAM
  changes, 7,130 root events and 3,038,616 errors; October (27 of 31 days) is built with the four missing days listed;
  an empty evidence folder with `--require-cloudtrail` exits 3.
