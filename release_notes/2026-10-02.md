## Why

A network STAR ticket (a browser DNS lookup of an uncommon-TLD domain) was investigated
twice, once by an automated run and once by hand. The two runs reached the same verdict on
different firewall evidence. Neither run's numbers were right:

- The automated run projected `hostname` on `NetworkFortigateTraffic`, got null on every
  row, and saved an account note saying the column is "not populated". The column does
  not exist on that table. Site names are on `NetworkFortigateEvent` (web filter), which
  that run never queried, so it never found the page that made the lookup.
- The manual run summed `sentbyte` / `rcvdbyte` and counted rows. The byte columns are
  cumulative per session, and the account's internal and perimeter FortiGates each log
  every flow under their own `sessionid`. Session counts and byte totals came out several
  times too high.
- Neither run anchored more than one occurrence of a lookup that recurred on several days.
  The manual run then sampled three. All of them sat inside the same site's page loads,
  which is what explained the recurrence.

## Changes

- New `references/fortigate.md`: which table answers which question; the three Traffic
  traps (duplicate devices, including when NAT between firewalls in series breaks the
  client-side key; cumulative bytes; `accept` rows are updates); window sizes and
  pacing; F1 trigger, F2 aftermath, F3 control; what goes in the closure.
- New bundled queries: `fw_trigger_hosts.kql` (web-filter hosts ±1 min around one raw event
  time), `fw_aftermath_sessions.kql` (one row per flow to the resolved addresses for
  +60 min, keyed on `srcport` + `dstip` + `dstport`, `max()` of the byte counters),
  `fw_host_sessions_control.kql` (the host's 20 largest flows in the same window: the
  visibility control and the yardstick for "small").
- `references/workflows/sentinelone.md`: the network STAR check runs the three queries.
  `hostname` is Event-only; flows, not rows; a recurring lookup gets several anchors. New
  verdict shape for a domain served by a site the user keeps open.
- `SKILL.md`: placeholders `{SRCIP}` and `{T0}`; the reference is in the assets table and in
  step 4's time-column trap.
- `references/workflows/generic.md`: points per-host firewall questions at the reference.
