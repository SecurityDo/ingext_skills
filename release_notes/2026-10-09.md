# 2026-10-09 — incident-investigation 1.2.22 → 1.2.23

On a hybrid tenant that uses Duo: name the person who changed the password, read the Duo
enrolment behind a "new auth device" alert, and count the phones on an address as well as
the sign-ins.

| Skill | Version | Status |

## Why

An automated run closed a new-user ticket correctly as benign. The ticket combined three
rules: a Duo "new auth device", an Entra "user added an authentication method", and a
first-seen sign-in. The run tied the new device to its own enrolment, but it missed the
strongest evidence for its own verdict and got one fact wrong:

- **It never asked who changed the password.** Entra showed the on-prem directory sync
  changing the password minutes before the first good sign-in, and the run called it
  "routine propagation". The domain controllers' Security log, which the tenant
  collects, showed the user failing Kerberos logons with a wrong password from internal
  workstations. An IT admin then reset the password and unlocked the account, and the
  user's first good logon followed. A helpdesk admin helping a locked-out user is
  what settles the ticket, and the sync row hides who did it.
- **It placed the user at home when they were in the office.** The MFA registration came
  from an IPv6 address nobody else used, and the run called it the user's home. That
  address was the IPv6 side of the same dual-stack browser whose IPv4 sign-ins, in the
  same seconds, came from the office network. The internal addresses in the DC log
  confirmed the user was on site.
- **It undercounted the office network.** The sign-in census found a handful of users on
  the address. Duo showed it as the network that dozens of staff phones authenticate
  from. Phones never appear in the sign-in log.

## Changes

- **office365.md 3a:**
  - On a Duo tenant, also run `duo_ip_census` over the ticket's addresses. It counts
    users by the computer side and by the phone side.
  - An IPv6 address and an IPv4 address seen in the same seconds are one dual-stack
    client. Resolve them as one location, and never read a unique IPv6 address as
    "home".
- **office365.md 3b, new "Duo (external MFA)":**
  - Run `duo_device_history`. An `enrollment` row for the same device key just before
    the flagged approval means the device is newly enrolled, not substituted; then ask
    who enrolled it.
  - A later approval where the phone and the computer share an address ties the phone
    to the user.
  - On a days-old account, every first-seen rule fires at the first sign-in.
- **office365.md 3c, new "Who changed the password on a hybrid account?":**
  - When Entra shows the directory sync changing the password, run
    `onprem_password_events` (4723/4724/4738/4740/4767/4768/4771/4776 for the
    subject).
  - Run `onprem_resetters` as its control and base rate.
  - Read the internal client addresses as location evidence.
  - `EventTime` is the DC's local time.
- **office365.md "Tables used":** a tenant whose `list_data_tables` names `Duo` is
  queried as `DuoAuthentication`. Selecting nested fields from `Duo` returns nulls, not
  an error.
- **Four new bundled queries,** each validated and run against the case above:
  - `duo_device_history`
  - `duo_ip_census`
  - `onprem_password_events`
  - `onprem_resetters`
- **SKILL.md:**
  - The Office365 routing row now covers `Duo_` rules on a Microsoft 365 user, and
    names the new 3a, 3b and 3c checks.
  - New `{SAM}` placeholder.
