# 2026-08-06 — ingext-promql search cost/compressed metrics released (1.0.3) + scope sync

One skill update. `ingext-promql` gained six `lake_search_*` / `lake_realtime_search_*` counters
in its cached metrics catalog (added in `ff8a483 "add new search metrics"`), taking the end-user
set from **twelve to seventeen counters** across the same six families plus the one gauge. That
commit shipped the catalog rows but never bumped the version or updated the skill's scope prose —
which still capped the count at twelve and listed "billing meter" and "compressed-byte counters"
as out of scope. Because the skill enforces a hard allowlist ("reject anything not in this
catalog"), the stale prose contradicted the catalog and would have caused the newly added cost and
compressed counters to be rejected. This release bumps the version and reconciles that language,
and rebuilds the cowork `.skill` package, which was still at 1.0.2 and predated the June metrics
addition entirely. For what the skill does and its trigger phrases, see its section in the root
`README.md`.

## Implementation notes

- **ingext-promql (1.0.2 → 1.0.3)** — released the search-metrics catalog addition and fixed the
  now-stale scope language it introduced.

  - **Five new counters surfaced** in `references/metrics_catalog.md` (§5 `lake_search`, §6
    `lake_realtime_search`), all carrying the existing `account` / `index` / `provider` labels:
    - `lake_search_compressed` — on-disk / compressed search byte count.
    - `lake_search_pod_seconds` — billable search-pod occupancy (60-second floor per pod).
    - `lake_search_core_seconds` — `pod_seconds × 1.5` (pod CPU request).
    - `lake_search_cost_millicents` — search cost in thousandths of a cent (`= 3.5 ×
      pod_seconds`; ÷1000 for cents, ÷100000 for dollars).
    - `lake_realtime_search_compressed` — on-disk / compressed realtime-search byte count.

    Cost counters are SaaS on-demand search only (`AccountSearchManagerV2`); realtime search runs
    in-process and emits no pod/core/cost series. Worked cost/CPU/spend example queries were added
    alongside the rows, and the quick-reference table now documents the cost counters.

  - **Scope reconciliation (the reason the bump was more than a version line).** The counter total
    in `SKILL.md` and the catalog scope rule was corrected **twelve → seventeen**. The out-of-scope
    exclusion list, which had blanket-excluded "billing meter" and "compressed-byte counters," was
    narrowed to **component-level** compressed-byte counters, with an explicit note that the
    `lake_search_*` cost and compressed counters are in the catalog and therefore in scope. Without
    this, the skill's hard allowlist check would have rejected the very metrics being released.

  - **Cowork package rebuilt.** `cowork/ingext-promql.skill` was regenerated from the updated
    source. The previous package was at **1.0.2** and did not contain the June search-metrics
    catalog rows at all, so this is the first cowork build to carry them. Layout unchanged: a ZIP
    with the `ingext-promql/` archive root holding `SKILL.md` and `references/metrics_catalog.md`.
