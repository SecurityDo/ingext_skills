# 2026-07-24 — connector-skills rollout: 14 per-application setup skills

The build-now pass of the connector-skills rollout (`plans/connector-skills-rollout.md`). The
plan inventoried all 54 live connector templates and specced one dedicated onboarding skill per
template; on review, **all open research items (R1–R11) were deferred to a separate
documentation-update project**, every skill gated on one was skipped rather than guessed, and
the remaining 14 shipped here (plan §9a). Each new skill pairs **cited vendor-side guidance**
(create the API credential, configure the export — every claim verified against vendor
documentation at build time, or explicitly marked UNVERIFIED) with an **automatic Fluency-side
install**: all are self-contained, ending in `create_connector` themselves, so
`customer-onboarding` routes to them directly with **no `add-connector` follow-on**.

## Implementation notes

- **Shared blueprint.** Every skill follows the `setup-okta-connector` section order (What this
  creates → Prerequisites → The offer → vendor runbook → Ingext install → onboarding hand-off →
  Output JSON → Verification → Failure modes → Security notes), with `assets/references.md`
  carrying a claim→source table ("Verified 2026-07-24") and `evals/evals.json` carrying four
  house-format evals including the `[Invoked from customer-onboarding]` hand-off. Layout:
  `SKILL.md` + `assets/` + `evals/`, packaged to `cowork/<name>.skill` (skill-name-root zip,
  extraction verified byte-identical, executable bits preserved).

- **The research protocol held.** Vendor steps were verified against live documentation
  (primary vendor docs; SIEM-vendor integration guides cited as labeled secondaries where
  vendor docs are login-gated — SentinelOne, parts of Mimecast and Proofpoint TAP). Remaining
  honest gaps are explicit in the skills rather than guessed: SentinelOne's least-privilege
  built-in role name (docs gated) and token-expiry variance ("the expiry the console shows is
  truth"), Box's client-secret rotation control, whether the platform supports in-place HEC
  token rotation (`setup-hec-passthrough`), a Setup-menu path for checking the Salesforce Event
  Monitoring license, and whether Trend's Auditor role covers every endpoint the connector
  polls (start at Auditor, escalate only on 403s).

- **Live-template divergences discovered at build time** (the skills always re-fetch live):
  several templates carry **no `datalake`/`index` parameters** (SophosEDR, TrendMicroVisionOne,
  Bitwarden, BoxCom, ProofpointTAP, BitdefenderST, SalesforceEM) — those skills and their
  catalog rows mandate `list_data_tables` before naming a table. A sibling `SentinelOne`
  template (distinct from `SentinelOneAPI`) exists in the live list and is handled as an
  anti-trigger/variant check. Verification also corrected the plan's believed Mimecast path
  (**Integrations** → API and Platform Integrations, not "Services →").

- **Two non-SaaS shapes.** `automatic-amazon-guardduty` is Mode A/B like the Azure `automatic-*`
  skills: a bundled idempotent `setup-ingext-guardduty.sh` (aws CLI; bash only — deviation
  justified in-skill) creates the least-privilege IAM user with the AWS managed
  `AmazonGuardDutyReadOnlyAccess` policy and an access key, JSON-only stdout, confirmation
  prompt, two-key-limit handling; GuardDuty itself must already be enabled (never enabled by
  the skill — billable), with GuardDuty **sample findings** as the quiet-account smoke test.
  `setup-bitdefender-securitytelemetry-connector` and `setup-hec-passthrough` run the
  **inverted HEC flow** — install first, because `create_connector` is what mints the HEC
  url + token the vendor side consumes — and their onboarding hand-offs mandate ⏳ (not ❌)
  while zero rows is the expected pre-streaming state. Honest-latency outlier: Salesforce
  hourly EventLogFiles lag **~3–6 hours**.

- **Router integration.** `customer-onboarding` (1.3.0): named vendors now check
  `references/application_catalog.md` for a Guided row before falling back to `add-connector`;
  the catalog gained a compact **"SaaS API & push integrations (guided)"** table (14 rows:
  aliases, prerequisites, datalake table, honest latency) and its Standard table now points the
  Bitdefender/Proofpoint variant forks at the guided siblings. `add-connector` (1.1.0): alias
  list refreshed against the live catalog (CrowdStrike **Falcon** now exists — the old
  "CrowdStrike → not available" example was stale and is replaced — plus Cortex XDR, Okta, Box,
  Duo, Mimecast CG/legacy; FortiGate V1 dropped from the primary alias), and a note added to
  offer the dedicated setup skill when the vendor-side work hasn't been done yet.

- **README.** "Skills at a glance" rows plus a new **"Connector setup (per-application)"**
  section for all 14; also backfilled the missing rows/sections for the three earlier
  `automatic-*` skills (azureaudit, defender, ms-eventhub).
