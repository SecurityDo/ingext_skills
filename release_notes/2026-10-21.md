## What changed

- New resource table: `office365ConditionalAccessPolicy` (56 fields, 5 example queries),
  from `ingext_schema` 08cb43e (`datatypes/Office365Resources/`). It is a snapshot table:
  one row per policy, current state, so queries take no time filter and no dedup step.
  - The schema warns about five traps. MFA can come from `authenticationStrength` while
    `builtInControls` is empty. `grantControls` is null on session-only policies.
    `mv-expand` of an empty array still yields a row. `createdDateTime` is null on older
    policies. Graph adds `@odata.context` keys that mean nothing.
  - The example queries cover: the posture inventory, legacy-auth block coverage, users
    excluded from enabled policies, report-only and disabled policies, and recent changes.
- **SKILL.md:** the table is added to the list of example resource tables.
- No other table changed. `--check` passes against `ingext_schema` (49 tables, `ASSET`
  kept). `cowork/ingext-kql.skill` rebuilt.

# 2026-10-21 — incident-investigation 1.4.3 → 1.4.4

| Skill | Version | Status |
| --- | --- | --- |
| incident-investigation | 1.4.4 | released |

**New S4 check in the SentinelOne workflow: earlier verdicts on the same file, across
hashes.** S4 searched for earlier copies by SHA-1 only. A vendor update ships a new hash,
so a fleet agent's new build always looked new to the tenant. On one ticket the Agent
Portal escalated a behavioural "Ransomware" detection of a management agent's service
binary over storyline indicators it could not attribute. The previous build of the same
binary, on another host, had been flagged with the same label and engine and carried every
one of those indicators. The customer had closed it as a false positive. Only a search by
file name found it.

- The new search filters on the exact `threatName`, excludes the ticket's own hashes, and
  reads facets only. One threat record is about 20k tokens.
- A copy counts as the same program only if it has the same install path and signer.
- The indicator comparison lists what the earlier, cleared copies do not cover. Those
  indicators still go to S2's attribution question.
- A zero means "no earlier copy updated in 30 days", because the index re-writes a threat
  only when it changes.
- New verdict-shape row: benign on a cleared precedent that covers every indicator, with
  a certificate-plus-path exclusion as the tuning.

Run on a live account. The search returned the earlier build's threat (a different hash,
`false_positive`). Its control, with the hash exclusion removed, returned the ticket's own
threat. The indicator facet showed all 25 of the ticket's indicators on every copy.
